1Requisitos

Tu servidor ya tiene casi todo. AegiFitness necesita:

  • Ubuntu Server con Docker y Docker Compose (ya lo tienes)
  • Red Docker proxy externa donde vive Nginx Proxy Manager (ya existe)
  • Cloudflare Tunnel apuntando a NPM (ya existe)
  • ~2 GB de RAM libres para construir las imágenes en el servidor (la API .NET y el build de Vite se compilan dentro de Docker)
  • Un subdominio para la app, ej: fitness.tudominio.com

Nota: A diferencia de AegisDocs, AegiFitness sí lleva backend: API ASP.NET Core, PostgreSQL y Redis. Todo viaja en el mismo docker-compose.yml — no instalas nada más en el host.

2Arquitectura General

Internet
    ↓
Cloudflare DNS
    ↓
Cloudflare Tunnel (cloudflared)
    ↓
Nginx Proxy Manager  ──► red "proxy"
    ↓
aegifit-web   (Nginx: sirve la PWA y proxifica /api)
    ↓           red "internal" (privada, no expuesta)
aegifit-api   (ASP.NET Core 10)
    ↓
aegifit-db (PostgreSQL 17)  +  aegifit-redis (caché)

Esta arquitectura es:

  • Segura la base de datos y Redis nunca salen de la red interna
  • Simple un solo compose levanta todo el stack
  • Coherente mismo patrón que AegisDocs: NPM → contenedor por nombre
  • Portable respaldar = copiar un volumen

3Estructura del Servidor

Crea la carpeta del proyecto junto a tus otras apps:

/home/keor/AegiFitness/
├── docker-compose.yml     ← orquesta los 4 contenedores
├── client/                ← código del frontend (se compila en el build)
│   ├── Dockerfile
│   ├── nginx.conf
│   ├── package.json
│   └── src/ ...
└── server/                ← código del backend (se compila en el build)
    └── AegiFitness.Api/
        ├── Dockerfile
        └── ... (API .NET)

Importante: a diferencia de AegisDocs (que monta archivos estáticos), aquí las imágenes se construyen en el servidor con docker compose up -d --build. Por eso debes subir el código fuente completo de client/ y server/.

4Instalación Paso a Paso

Paso 1: Verificar la red proxy

docker network ls | grep proxy
# Si no existiera: docker network create proxy

Paso 2: Crear la carpeta y subir el código

mkdir -p /home/keor/AegiFitness

Desde tu PC (WinSCP, scp o rsync), sube todo el proyecto:

# En Windows, desde la carpeta del repo:
scp -r client server docker-compose.yml user@tu-servidor:/home/keor/AegiFitness/

# O con rsync (más rápido en actualizaciones):
rsync -avz --delete client/ user@tu-servidor:/home/keor/AegiFitness/client/
rsync -avz --delete server/ user@tu-servidor:/home/keor/AegiFitness/server/
scp docker-compose.yml user@tu-servidor:/home/keor/AegiFitness/

Tip: no subas node_modules/, dist/, bin/ ni obj/. Los builds ocurren dentro de Docker. (rsync --delete con esas carpetas excluidas localmente ya está bien; los .dockerignore incluidos las filtran del build de todas formas.)

Paso 3: (Opcional) Editar claves antes del primer arranque

Abre docker-compose.yml y ajusta si quieres: POSTGRES_PASSWORD, Jwt__Key y SEED_ADMIN_PASSWORD (la contraseña inicial del usuario admin). Para uso personal puedes dejarlas como están.

Paso 4: Construir y levantar

cd /home/keor/AegiFitness
docker compose up -d --build

La primera vez tarda varios minutos: descarga las imágenes base, compila la API .NET, compila el frontend y siembra la base de datos (roles, usuario admin, 185 ejercicios y 140 comidas).

Paso 5: Verificar que todo está sano

docker compose ps
# Los 4 contenedores deben estar "Up" (db y redis "healthy")

docker logs aegifit-api --tail 20
# Debe verse: migraciones aplicadas + "Now listening on: http://[::]:8080"

# Probar la API a través del contenedor web:
docker exec aegifit-web wget -qO- http://aegifit-api:8080/api/health
# {"status":"ok"}

6Cloudflare Tunnel

En tu configuración de cloudflared (ej: /root/docker/cloudflared/config.yml), agrega el hostname apuntando a NPM:

- hostname: fitness.tudominio.com
  service: http://npm:80

Luego reinicia el túnel:

docker restart cloudflared

7Nginx Proxy Manager

En tu panel de NPM, crea un Proxy Host:

CampoValor
Domain Namesfitness.tudominio.com
Schemehttp
Forward Hostname / IPaegifit-web
Forward Port80
Cache AssetsOFF (la PWA gestiona su propio caché)
Block Common ExploitsON

En la pestaña SSL:

  • SSL Certificate: Request a new SSL Certificate
  • Force SSL: ON
  • HTTP/2 Support: ON

No actives "Cache Assets": el Service Worker de la PWA necesita respuestas frescas de sw.js y del manifest, y el nginx interno ya aplica las cabeceras de caché correctas para los assets.

8Primer Acceso y Licenciamiento

  1. Abre https://fitness.tudominio.com (te llegará la PWA instalable: en el móvil, "Añadir a pantalla de inicio").
  2. Inicia sesión con el usuario semilla: usuario admin · contraseña la de SEED_ADMIN_PASSWORD del compose (por defecto Admin#2026!).
  3. Completa el onboarding (datos, objetivo, configuración semanal) — el admin también es usuario 1 con su propio plan.
  4. Cambia la contraseña de admin cuando puedas.

Licenciar a otros usuarios

  1. La otra persona entra a la URL y se registra (usuario y contraseña únicos).
  2. Su cuenta queda en estado pendiente: puede iniciar sesión pero no usar nada.
  3. Tú entras como admin → Admin en el menú → filtro pending → Aprobar (opcionalmente con vigencia en días).
  4. Desde el mismo panel puedes Suspender, Revocar, Extender la licencia u otorgar el rol Admin.

9Actualizar la App

Cuando tengas cambios nuevos en el código:

  1. Sube el código actualizado:
rsync -avz --delete client/ user@tu-servidor:/home/keor/AegiFitness/client/
rsync -avz --delete server/ user@tu-servidor:/home/keor/AegiFitness/server/
  1. Reconstruye y reinicia:
cd /home/keor/AegiFitness
docker compose up -d --build

La base de datos no se toca: vive en el volumen aegifit-pgdata y las migraciones se aplican solas al arrancar la API.

Tip: si solo cambiaste docker-compose.yml (claves, por ejemplo), basta docker compose up -d — recrea los contenedores sin reconstruir imágenes.

10Cambiar Claves

Todas las claves están en docker-compose.yml, sección api → environment y db → environment:

VariableQué esNota
POSTGRES_PASSWORDContraseña de PostgreSQLSi la cambias tras el primer arranque, recrea el volumen (ver abajo)
ConnectionStrings__DefaultCadena de conexión de la APIDebe llevar la misma contraseña que POSTGRES_PASSWORD
Jwt__KeyFirma de los tokens JWTMínimo 32 caracteres; al cambiarla se cierran todas las sesiones
SEED_ADMIN_PASSWORDContraseña inicial del adminSolo se aplica en el primer arranque (con la BD vacía)

Tras editar:

docker compose up -d

Ojo: POSTGRES_PASSWORD solo inicializa la base de datos la primera vez. Si la cambias con datos existentes, la API no podrá conectar hasta que actualices también la contraseña dentro de PostgreSQL — o borres el volumen y empieces de cero (docker compose down -v, destruye los datos).

11Respaldos de la Base de Datos

Todo el estado de la app (usuarios, perfiles, planes, logs, XP) vive en PostgreSQL:

Respaldar

docker exec aegifit-db pg_dump -U aegifit aegifitness | gzip > aegifitness-$(date +%F).sql.gz

Restaurar

gunzip -c aegifitness-2026-07-17.sql.gz | docker exec -i aegifit-db psql -U aegifit -d aegifitness

Respaldo completo (volumen)

docker run --rm -v aegifit-pgdata:/data -v $(pwd):/backup alpine \
  tar czf /backup/aegifit-pgdata-$(date +%F).tar.gz -C /data .

Sugerencia: programa un cron semanal con el pg_dump y guarda el archivo junto a tus otros respaldos.

12Solución de Problemas

SíntomaCausa probableSolución
502 Bad Gateway después de reiniciar o redeplegar Nginx resolvía la IP de api una sola vez al arrancar; al recrearse api con otra IP, el proxy quedaba apuntando a una IP muerta Corregido en v1.1: nginx.conf ahora usa el DNS de Docker (resolver 127.0.0.11) y re-resuelve en cada request. Redeploy: docker compose up -d --build --force-recreate
aegifit-web en bucle de reinicios Nginx moría al arrancar ("host not found in upstream") si api aún no existía en DNS Corregido en v1.1: web ahora espera a api: service_healthy y el proxy ya no depende del DNS de arranque
aegifit-api aparece unhealthy en docker compose ps Las migraciones automáticas aún corren (hasta ~60s) o fallaron contra una BD con esquema viejo docker logs aegifit-api --tail 100. Si es error de migración por esquema viejo: docker compose down -v (borra datos) o migra la BD a mano
La página carga pero dice "Error de conexión" La API no está sana o NPM no alcanza aegifit-web docker compose ps y docker logs aegifit-api --tail 50; verifica que aegifit-web está en la red proxy: docker network inspect proxy | grep aegifit
Login válido pero rebota a /login La API no responde o el JWT cambió Revisa logs de la API; si cambiaste Jwt__Key, vuelve a iniciar sesión
La API reinicia en bucle No conecta a PostgreSQL docker logs aegifit-db; verifica que la contraseña del compose coincide en db y api
El build falla por memoria Poca RAM para compilar .NET + Vite a la vez Construye por partes: docker compose build api y luego docker compose build web
Cambios del frontend no se ven Service Worker viejo en el navegador Recarga forzada (Ctrl+Shift+R); la PWA se actualiza sola al detectar el nuevo SW
Empezar de cero — docker compose down -v && docker compose up -d --build (destruye TODOS los datos)

Logs útiles

docker logs aegifit-api --tail 100 -f    # API (migraciones, seed, errores)
docker logs aegifit-web --tail 50        # Nginx del frontend
docker logs aegifit-db --tail 50         # PostgreSQL
docker compose ps                        # estado general (todos deben decir "healthy")

Verificación post-deploy

docker exec aegifit-api curl -fsS http://localhost:8080/api/health   # {"status":"ok"}
docker exec aegifit-web wget -q -O- http://localhost/healthz             # ok
docker exec aegifit-web wget -q -O- http://localhost/api/health          # proxy web → api
