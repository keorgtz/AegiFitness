Contexto
Cierre del pulido UI/UX + corrección de contratos API
Se completaron los ajustes responsive pendientes de la revisión visual y se corrigieron dos desajustes de contrato entre el backend y el frontend que causaban un crash en la vista Hoy (TypeError: reading 'name') y pérdida silenciosa de la referencia a la comida al registrar comidas del plan.
Correcciones de contrato API
  • WorkoutLogDto.entries ahora incluye el objeto exercise completo (nuevo WorkoutLogEntryResponseDto). El GET ya lo incluía en la consulta pero el mapeo lo descartaba — era la causa del crash en Hoy y del fallo móvil del E2E.
  • MealLogDto.entries ahora incluye food (nuevo MealLogEntryResponseDto, null para comidas custom). El frontend ya lo esperaba como opcional.
  • MealPlanItemDto ahora expone foodId: el cliente lo declaraba en su tipo pero el servidor no lo enviaba, así que "La comí" registraba comidas sin referencia al alimento del plan.
  • Los POST de workout-logs y meal-logs recargan la entidad con sus includes antes de responder, devolviendo el contrato completo.
  • Progreso: la adherencia ya no se multiplica por 100 en el cliente (el servidor devuelve 0–100). Antes mostraba 2900 %; ahora 43 % / 10 % correctos.
  • meal-plans/today y meal-plans/regenerate recargan el plan con Include(Items → Food) tras generarlo — el generador no trae la navegación y Map lanzaba 500 al regenerar planes (detectado por el smoke de API).
Smoke scripts versionados
  • scripts/run-smoke.ps1 — 38 checks de API: auth, refresh, perfil, config, planes, logs (con exercise/food), métricas, gamificación, metas, dashboard y catálogos. Levanta la API, verifica y la detiene; exit 0/1.
  • scripts/run-smoke-admin.ps1 — 17 checks de administración: filtros, approve, edición, reset de contraseña con relogin, licencia con vencimiento/lifetime/extend, roles (grant/revoke, autoprotección 400), suspend (bloqueo 403) y revoke.
  • Ambos aceptan -Port y -SkipBuild; por defecto compilan Debug antes de ejecutar.
Pulido UI / responsive
  • Logros: contadores con count-badge en línea y metas sin decimales innecesarios (5 / 5 en vez de 5.0 / 5.0).
  • Admin móvil: tabla reemplazada por tarjetas admin-user-card; usuarios no activos sin vencimiento muestran "Sin licencia" en vez de "De por vida".
  • Nutrición: macros de cada comida con separadores y flex-wrap — fin del texto encimado "954 kcal43g P1.3 porciones".
  • Gráficas de barras: etiquetas a 9 px con más separación; "Core" ya no se trunca.
  • Segmented control en móvil: padding y fuente reducidos bajo 480 px para que "Pendientes" quepa sin truncarse.
Entrenamiento: nueva UX + sustitución de ejercicios
  • Cambiar ejercicio: cada tarjeta del entreno tiene botón swap_horiz que abre un modal de sustitución filtrado por el mismo grupo muscular (con toggle para ver todos) y por la modalidad del día (gym/calistenia). El plan sigue siendo recomendación; el log registra lo que realmente hizo el usuario. Sin cambios de backend: el contrato de workout-logs ya acepta cualquier ejercicio y devuelve exercise completo.
  • Anti-duplicados: el modal excluye los ejercicios ya presentes en otras tarjetas de la sesión y deduplica filas por nombre (el seed repite nombres con distinto objetivo).
  • Chip Cambiado cuando el ejercicio registrado no es el del plan; persiste tras guardar y recargar.
  • Tarjetas rediseñadas: badge numerado con acento por grupo muscular (tokens semánticos existentes, 0 colores nuevos), muscle-tag por grupo, acciones guía/cambiar como icon-action, franja de prescripción del plan (series×reps · descanso · equipamiento) y fila de tracking separada por divisor. Menos apretadas, menos monótonas.
  • scripts/verify-swap.mjs (nuevo): 13 checks E2E del flujo completo de sustitución (UI → guardado → contrato API → persistencia tras recargar → móvil).
  • Fix en scripts de verificación: usaban fecha UTC (toISOString) mientras la app trabaja en fecha local — entre las 18:00 y medianoche local los scripts limpiaban y leían el día equivocado. Ahora usan fecha local yyyy-MM-dd.
Segunda iteración UX: steppers, diálogos móviles y swap de platillos
  • Steppers sin encimado: en las tarjetas de ejercicio, Series/Reps/Peso desbordaban su columna (~132px necesarios en ~80-118px disponibles) y los botones +/− se tocaban entre tarjetas vecinas. Ahora son un control segmentado conectado (un solo borde, botones de 34px, valor flexible, unidad en el label) — físicamente imposible que se encimen, simétrico a cualquier ancho.
  • Diálogos móviles bottom-sheet: el Modal se renderizaba inline; cualquier ancestro con transform/filter convertía position:fixed en relativo a ese ancestro y el diálogo se encimaba con el contenido. Ahora usa createPortal a <body> + bloqueo de scroll del fondo + role="dialog" aria-modal. En móvil vertical los diálogos son bottom-sheet de ancho completo (88dvh máx, safe-area, animación slide-up) — verificado: guía de ejercicio y recetas ya no se solapan con header ni bottom-nav.
  • Cambiar platillo (como el de ejercicios): nuevo endpoint PUT /api/meal-plans/items/{id}/swap que cambia el FoodId y recalcula las porciones para mantener las calorías (954 kcal → sustituto de 420 kcal/u = 2.3 porciones ≈ 966 kcal). Persiste en el plan del día.
  • FoodSwapModal compartido (Today + Nutrición): filtro por mismo tipo de comida con toggle, dedupe por nombre y ordenado por proteína más cercana al platillo original — para "comer otra cosa con protes similares".
  • Fix E2E: Card interactive renderiza <button> raíz y el botón de swap anidado era HTML inválido (hydration error). Las tarjetas de Nutrición ahora tienen acciones explícitas (cambiar / receta) y el nombre como botón de texto.
  • verify-swap.mjs ampliado a 22 checks: swap de ejercicio, swap de platillo (UI → API → persistencia), bottom-sheet móvil (ancho completo, pegado abajo).

Docker: resiliencia de deploy
  • client/nginx.conf: eliminado el bloque upstream (DNS resuelto una sola vez al arrancar → 502 permanente si api se recreaba con otra IP, y crash-loop de nginx si api aún no existía en DNS). Ahora usa resolver 127.0.0.11 valid=10s + proxy_pass con variable: re-resuelve en cada request. Añadido endpoint /healthz.
  • server/AegiFitness.Api/Dockerfile: instalado curl en la imagen runtime para el healthcheck.
  • docker-compose.yml: healthcheck de api (/api/health, start_period: 90s para las migraciones con reintentos), healthcheck de web (/healthz) y web depends_on api: service_healthy.
  • deploy-guide.html v1.1: nuevos modos de fallo documentados (502 tras reinicio, bucle de nginx, api unhealthy) y comandos de verificación post-deploy.
